# Outline — Fix the harness before you switch models

- **Hook:** When a coding agent disappoints, swapping the model is the first instinct. That's like replacing the engine when the problem is the dashboard, the checklist, and the toolbox.
- **Promise:** A four-part harness audit — context, verification, state and progress files, and tools — you can run on your own setup in about an hour.

## Sections
1. Why the harness is the first lever — claims #1, #2, #3, #4; counterpoints 1, 2
2. Context — what the agent sees every turn — claims #5, #6, #12; counterpoint 4
3. Verification — don't let the builder call the work done — claims #9, #10
4. State and progress files — a fresh session should not have to guess — claims #9, #11
5. Tools — a short, named list beats a pile of unused ones — claims #12, #9
## Close
Run the four checks before you pay for a model swap. If the same hard tasks fail in every harness, that is a ceiling problem (claim #4). Do not treat public leaderboard gaps as a clean harness win (claims #7, #8; counterpoint 3). Cheap first measurement: ten of your own recent tickets, with and without your current progress-file and test-hook setup.
